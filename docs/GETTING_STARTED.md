# Goodcase v0.1

웹 프로젝트로 가져가서 스타일을 바꾸는 React + TypeScript 참조 구현입니다. 실행 갤러리에서 동작을 확인하고 계약·원본 코드·이식 방법을 한곳에서 읽습니다.

## 실행

```sh
git clone https://github.com/Leonamin/goodcase.git
cd goodcase
pnpm install --frozen-lockfile
pnpm dev
```

`pnpm dev`는 `0.0.0.0:5179`에 바인딩합니다. 이 컴퓨터에서는 http://localhost:5179, 같은 네트워크의 다른 기기에서는 `http://<컴퓨터의 LAN IP>:5179`로 갤러리에 접속합니다.

```sh
pnpm typecheck
pnpm build
pnpm test
pnpm storybook
pnpm build-storybook
```

Storybook은 http://localhost:6019 에서 실행합니다. 컴포넌트별 독립 예제와 실제 갤러리 부모 화면을 공유합니다.

## 탐색과 검토

왼쪽에서 컴포넌트를 고르고 미리보기, 동작 계약, 코드, 가져오기를 확인합니다. 컴포넌트와 문서 탭은 URL로 보존되어 새로고침과 뒤로가기가 가능합니다. 테마·밀도·라이트/다크 모드는 토큰 교체를 보여주는 예제입니다. 검토 표시는 이 브라우저의 localStorage에만 보관합니다. 미리보기 초기화는 현재 예제의 상태를 새로 시작합니다.

## 코드 이식

1. 프로젝트의 동일 책임 컴포넌트를 먼저 찾습니다. 기존 구현을 확장할 수 있으면 중복을 만들지 않습니다.
2. 갤러리의 가져오기 탭에서 소스 ZIP을 받습니다. 해당 컴포넌트 모듈과 상대 import 의존 모듈, 공통 CSS, MIGRATION.md가 포함됩니다. 한 모듈의 다른 export도 포함될 수 있습니다.
3. 폴더 구조를 유지하거나 상대 import를 맞춥니다. React 19+와 TypeScript를 기준으로 구현했습니다. 오버레이는 radix-ui, 아이콘은 lucide-react를 사용합니다. ZIP에 실행 갤러리와 node_modules는 포함되지 않습니다.
4. CSS는 tokens → global → basic → overlays → tabs → toast → composed 순서입니다. global.css의 html/body 기본값은 대상 프로젝트 스타일과 비교해 필요한 규칙만 병합하세요. 반복 이식하면 CSS가 중복 추가되지 않게 관리하세요.
5. --gc-* 토큰을 프로젝트 의미 토큰에 연결합니다. Portal 오버레이도 같은 토큰을 읽도록 html/body 범위 또는 Portal 컨테이너에서 토큰을 공급합니다.
6. 예제 이벤트를 실제 API, 라우터, 업로드 adapter에 연결합니다. 파일 업로더는 실제 File을 읽지만 데모 업로드는 로컬 시뮬레이션입니다. 갤러리의 저장·삭제·목록 조회도 로컬 예제입니다.
7. 마우스, 키보드, 터치, 긴 텍스트, 좁은 화면, 실패·재시도·중복 실행을 원본 계약과 비교합니다.

## 구조

AI와 다른 프로젝트에서 사용할 설치용 스킬은 [스킬 배포본](SKILL_BUNDLE.md)을 참고하세요. `pnpm build:skill`로 재사용 자료만 포함한 폴더와 ZIP을 생성합니다.

- src/components/basic: 입력·표시·배치
- src/components/overlays: 선택·메뉴·모달·알림
- src/components/composed: 폼·목록·업로드·이미지 흐름
- src/catalog: 메타데이터와 예제. 제품으로 복사할 필요 없음
- src/styles/tokens.css: 참조 테마와 변형의 원본
- tests: 실제 브라우저 흐름 검증

## 범위

첫 버전은 이전에 정한 기본 컴포넌트, Typography/Stack/Grid/Divider, 10개 조합형 컴포넌트를 포함합니다. 날짜 범위 선택, 리치 텍스트, 트리, 드래그 정렬, 차트는 후속 범위입니다. 서버·인증·실제 파일 저장·외부 배포는 포함되지 않습니다. 프레임워크 변환(Flutter/Vue 등)은 자동 제공하지 않습니다.

## 변형 선택

Tabs는 underline(기본), adaptive(활성 라벨만 확장), segmented(전체 라벨), bottom(큰 아이콘 위·라벨 아래)을 제공한다. Bottom도 같은 페이지의 패널 전환이며 실제 페이지 이동은 Link 기반 내비게이션으로 구성한다.

Toast는 테마 surface를 기본으로 사용하고 tinted/solid 상태색 배경은 선택적으로 적용한다. timer는 bar/circle/none이며 자동 닫힘 정책과 표현은 별개다. 오류·액션은 기본 수동 닫기이며 해당 카드의 호버·내부 포커스에서만 타이머가 멈춘다. 탭 숨김은 모든 카드에 적용한다. 원형은 닫기 영역에서 남은 시간을 보여주고 호버·포커스 시 X를 보여준다. IconButton compact의 24px 높이는 제목 첫 줄·아이콘 컨테이너와 같다. 긴 제목은 줄바꿈하고 설명은 별도 줄에 둔다.

포커스 링은 외부로 확장되므로 부모 패딩과 인접 요소 간격에 --gc-focus-clearance(기본6px) 이상을 확보한다. 갤러리 Dialog는 실제 TextField·Combobox·Button으로 이 계약을 확인하는 예제다. 라이트/다크 선택은 data-color-mode를 사용한다. 이식할 프로젝트가 이미 테마를 갖고 있다면 프로젝트의 변수와 테마 신호를 연결한다.

ToastProvider의 layout="stack", stackSize=N으로 겹침을 선택한다. 목록을 호버하거나 F8로 포커스하면 펼쳐지며, 펼치기 자체는 다른 카드의 시간을 멈추지 않는다. 접힌 뒤쪽 카드는 읽기 전까지 일시정지하고 키보드 탐색에서 제외한다. 먼저 도착한 N개를 표시하고 나머지는 FIFO 대기열에 보존한다. direction="up"은 하단에서 아래→위, "down"은 상단에서 위→아래로 나타난다. 닫기·만료는 오른쪽 이동과 페이드 후 제거한다. 모션 감소에서는 이동 없이 제거한다. 타이머는 프레임마다 React를 갱신하지 않는 브라우저 애니메이션과 단조 시계로 동기화한다.

ImageViewer는 브라우저 뷰포트를 채우는 모달이다. 이미지·도구·썸네일을 제외한 빈 배경 클릭/터치로 닫을 수 있다. 이미지 배열과 index, 열림 상태는 호출부가 소유한다. 모바일에서는 화면 맞춤 상태에서 좌우 스와이프로 이미지를 전환하며 페이지가 손가락 위치를 따라간다. 확대 상태에서는 같은 제스처를 이미지 이동으로만 처리한다. 버튼·썸네일·키보드 전환에는 시간 기반 슬라이드 효과를 적용하지 않는다. isAnimated={false}는 스와이프를 놓은 뒤 위치 보정 효과만 끄며 OS의 모션 감소 설정도 따른다. 다른 프로젝트에 옮길 때 모달의 포커스 가두기·Escape·열기 요소 복귀, 배경 스크롤 잠금과 빈 공간 닫기 계약을 함께 유지한다.

Button과 IconButton의 눌림은 중앙 기준 축소다. --gc-press-scale(기본0.96), --gc-press-duration(기본80ms), --gc-press-easing으로 조정한다. CSS scale 속성을 사용해 배치용 transform과 충돌하지 않는다. 모션 감소 설정에서는 축소를 생략한다.

이미지 뷰어의 두 손가락 핀치는 100~400% 범위에서 확대·축소한다. 두 손가락이 들어오면 페이지 스와이프를 취소하고 핀치를 우선한다. 확대 상태의 한 손가락은 이미지 이동만 처리하며, 핀치 후 남은 손가락으로 이어서 이동할 수 있다. 화면 맞춤으로 돌아오더라도 같은 터치 흐름은 페이지 전환으로 바꾸지 않고, 손을 모두 뗀 다음 새 제스처부터 스와이프를 허용한다.

모바일에서는 이미지 위를 더블탭하면 탭한 콘텐츠 지점을 기준으로 200% 확대하며, 확대된 상태의 더블탭은 100% 화면 맞춤으로 돌아온다. 단일 탭과 드래그·스와이프·핀치는 더블탭으로 처리하지 않는다. 이미지 밖 빈 공간의 단일 탭 닫기는 유지한다.
