# ui-check

이 폴더의 `check.mjs`는 실행 중인 페이지를 키보드로 순회하며 불변식을 계산된 스타일로 측정한다. 컴포넌트·파일 이름은 모른다. `@playwright/test`가 필요하다.

| 불변식 | 실패 조건 |
|---|---|
| focus-clipped | 포커스 링이 overflow 조상 경계를 넘는다 |
| focus-invisible | 링도, 포커스 해제 대비 스타일 변화도 없다 |

```bash
node <이 폴더>/check.mjs <url...> [--crawl <css>] [--scope <css>] [--inject-css <css>] [--max 150]
```

`--crawl` 링크 수집 · `--scope` 순회 영역 제한 · `--inject-css` 로드 순서 재현. 문제가 있으면 종료 코드 1과 요소·원인·힌트를 출력한다.

## 절차

1. 문제 페이지에서 검사기를 실행한다. 잡히면 3으로 간다.
2. 안 잡히면 사용자의 말을 컴포넌트 이름 없는 한 문장으로 일반화한다.
   - 계산으로 측정할 수 있으면 `check.mjs`의 `inspectFocus`에 불변식을 추가한다. 먼저 결함이 있는 상태에서 실패하는지 확인한다.
   - 측정할 수 없으면(판단 문제) 코드는 건드리지 않고 사람에게 알린다.
3. 출력된 힌트를 후보로 삼아 대상 코드에 맞는 방법을 스스로 고른다. 힌트는 강제가 아니다.
4. 검사기를 다시 실행해 0건인지, 같은 범위 전체에서 새 문제가 없는지 확인한다.
5. 고친 코드를 임시로 되돌려 검사기가 다시 실패하는지 확인한다. 실패하지 않으면 검사기가 그 문제를 잡지 못한다.

## 제한

- 검사 통과가 목적이 아니다. 링을 지워서 통과시키지 않는다. `focus-invisible`이 대체 표시 없는 제거를 잡는다.
- 불변식을 추가하거나 완화하면 변경 내용을 사용자에게 보여 준다. 검사기를 약하게 만들어 통과시키지 않는다.
- 불변식 이름과 힌트에 컴포넌트·파일 이름을 쓰지 않는다. 사례를 문서에 쌓지 않는다.
- 토큰 값, 공용 컴포넌트 API 변경이 필요하면 수정 전에 사용자에게 묻는다.
- 계산은 근사다(`transform`, `clip-path` 무시). 오탐이 나오면 해당 불변식만 고친다.
